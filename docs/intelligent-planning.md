# 主动规划与真实路线证据

更新于 2026-09-17。支持自动选择地铁下车换打车的站点，以及多站活动的主动安排。

## 行为

配置高德 Key 后，自然语言单程和多站请求都进入真实地图规划流程，不再误入限定地点的合成图。结构化 `constraints` / `itinerary` 演示调用仍受 DATA_MODE 控制。餐厅不再是必填阻塞项：根据前一站查询附近门店，保留多个候选，计算接驳和停留后继续比较下一站。未指定活动时长时可以按明确标注的测算值推进；缺少关键日期和开场时间时只问优先问题，不要求用户先做完所有决策。

## 自动选择下车站

指定时刻支持中文/英文冒号、全角数字和冒号周围的空格，如 `22： 30` 与 `22:30` 等价。明确时刻保持为精确出发时间，不降成“晚上”的宽时间窗；仅修改时刻的追问保留原出行日期。结果首行展示实际查询出发时间，即使晚间候选全被淘汰，也不会提前到当前时间伪造可行路线。

输入“先坐地铁，然后打车”或“下车再打车”会设置 `ItineraryDraft.metro_then_taxi`。`src/search/night_transfer.py` 实现如下搜索，不需要用户提供下车站，也没有预设具体站名：

1. 取得起终点经济与省时路线，从中发现地铁线路和换乘站。即使全程赶不上末班，也保留线路信息用于扩展。
2. 用官方公交线路 ID 接口加载最多两条可接入线路的有序站点，按行进方向扩展更接近目的地的站点，与原路线换乘站组成最多八个候选。两种接口站点 ID 不一致时，用同名且相近的坐标匹配。
3. 对每个候选重新查询实际出发时间下的进站和乘车路线，不能用直线距离或线路站序证明可达。淘汰错过末班、末班信息缺失、赶车余量不足、等待至早班或步行超过五公里的路线。
4. 查询候选站到目的地的驾车时长与出租车估价，预留十分钟出站及等车，计算地铁票价加打车估价，再校验预算、禁用方式与到达期限。
5. 按排序偏好选择推荐站，聊天和卡片直接显示“在某站下车再打车”。费用缺失时不声称已经找到最便宜站点。

“10点半”结合赶末班语境按22:30测算，并显式展示这一理解；明确的“上午10点半”不会被改成晚上。新的单程请求会替换旧的多站草稿，后续“预算50元”保留当前路线和接驳要求。

边界：候选集有限，非全网最优证明；站点末班来自地图资料，未核验当天临时运营或短线折返。出租车估价不等于网约车报价，夜间加价、叫车成功率未核实，驾车耗时采用查询时路况。这里只承诺程序执行了选站判断，不能把参考方案当作实际价格和运营保证。

接口依据：[路径规划2.0](https://lbs.amap.com/api/webservice/guide/api/newroute) 的 `route.taxi_cost`、[公交线路ID查询](https://lbs.amap.com/api/webservice/guide/api-advanced/bus-inquiry) 的有序站点。所有查询沿用共享超时、重试、缓存和每轮调用上限。

例如“北京大兴清源路→天津奥体演唱会→海底捞→广州”，系统分别计算：

1. 可赶上开场的城内接驳、城际车次及天津接驳；
2. 不同门店对晚间交通、用餐结束时间和后续接续的影响；
3. 用餐后继续出发与次晨出发；
4. 全程累计费用、到达期限、禁用方式、是否跨夜和步行距离；
5. 如果候选冲突，展示提高预算或放宽到达期限后可能成立的接续，并明确它们尚不满足原条件。

## 数据与算法

`src/tools/amap_routes.py` 调用高德官方地理编码、公交路线和步行路线接口，复用超时、最多两次重试与缓存。`src/search/evidence.py` 将供应商响应转换成路线证据，重建时序；铁路使用返回的车次与时刻，不把供应商的总耗时直接当作最终到达时间。预留铁路进站 30 分钟、出站 10 分钟、公交候车 5 分钟；这是可解释的保守原型参数，未覆盖所有站点的真实条件。地铁/公交到站时刻属于推算值。

`src/agent/intelligent.py` 按活动顺序传播多标签候选，保留便宜和较早抵达的标签，每层最多 4 个候选；门店最多比较 2 个；末段同时搜索经济和时间短策略以及当晚/次晨分支。每请求最多 28 次工具调用并共享 30 秒期限。站点、车次由实际地图响应提供；LLM 不生成班次或票价。

默认累计步行上限为 5 公里。超过界限只表示当前搜索配置不接受该候选，不能据此宣称客观无解或全市场最优。当前未主动扩展多座出发机场、卧铺席别、酒店组合与不同天数的完整搜索空间。

## 输出契约

`metadata.intelligent_plan` 包含 `options`、已完成站数、测算条件、优先问题、淘汰原因、数据缺口和 `tradeoffs`。这些路线证据与已有 `plans` 分开，避免将余票尚未验证的地图结果冒充售票方校验后的计划。前端展示智能规划卡片和按时间顺序展开的活动/交通段。

`tradeoffs` 只提供调整条件的解释，不混入满足当前条件的候选。引用的交通费用是地图参考金额；含未知打车费用、餐饮或住宿时明确提示预算尚待核验。售票方服务日期、余票、实时票价仍未接入，返回的具体车次必须再次确认。

真实地图不等于数据完整：场馆先用 POI 匹配，入口可能不同；门店选择和常规营业时间不能保证演出当天营业、无排队。完整交通候选也不构成已核验的可预订方案。

## 验证

新增回归覆盖：列车实际时刻覆盖错误的汇总耗时、错过的列车不能移到次日、等待公交首班、跨日列车、全程成本决定门店、超预算只进入调整建议、失败时保留已完成部分，以及“需要具体车次”不再重复询问餐厅。

官方接口依据：[高德路径规划 2.0](https://developer.amap.com/api/webservice/guide/api/newroute)、[POI 搜索](https://developer.amap.com/api/webservice/guide/api/search/)。实际申请和密钥配置见 [API 接入说明](api-setup.md)。
